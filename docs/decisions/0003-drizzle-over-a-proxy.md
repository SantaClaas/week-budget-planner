# 0003 Drizzle 1.0 over a proxy to the leader tab

**Status:** Accepted, 2026-10-08.

## Context

Flashcut runs plain SQL through its database service and tracks its schema with `PRAGMA user_version`. This app adds a schema with migrations and typed queries on top of the same storage layer (see [0002](0002-sqlite-in-the-browser.md)). Only the leader tab has a database object; every other tab reaches the database through calls over BroadcastChannel. A user action that writes several rows must not have another tab's query land in the middle of it.

## Decision

Use Drizzle, `drizzle-orm` and `drizzle-kit` at `1.0.0-rc.4`, pinned exactly ([Drizzle](../spec/persistence.md#drizzle-new-compared-to-flashcut) in [Persistence](../spec/persistence.md)):

- **every tab** runs the same typed queries through `drizzle-orm/sqlite-proxy`, whose callback calls flashcut's database service, locally on the leader and over BroadcastChannel elsewhere;
- **migrations** are generated by drizzle-kit from [`src/database/schema.ts`](../../src/database/schema.ts) into [`drizzle/`](../../drizzle/), committed, never edited once applied, and run only on the leader with the filesystem-free Turso migrator, loading only the pending ones;
- **a user action that writes several statements** goes through Drizzle's batch, which the leader runs in one transaction.

## Alternatives

- **Drizzle 0.45, the stable line.** Rejected: the 1.0 line ships `drizzle-orm/tursodatabase/wasm` and the filesystem-free `wasm-migrator`, and 0.45 has neither.
- **Drizzle's Turso driver in every tab.** Not possible: follower tabs have no database object, so a driver that needs one can only run on the leader. The proxy driver needs nothing but a callback.
- **`database.transaction()` over the proxy.** Rejected: it sends BEGIN, each statement and COMMIT as separate calls, so another tab's query could land in between. The batch is one call.
- **Flashcut's `PRAGMA user_version` next to Drizzle's migration table.** Rejected: two records of which migrations ran could disagree.
- **Plain SQL without a query builder**, as in flashcut. Not recorded why it lost.

## Consequences

- **The 1.0 line is a release candidate too**, so it's pinned like Solid, and its types are checked before relying on a detail.
- **The proxy expects rows as arrays** in column order, so the leader's service has a method that returns them that way (Turso's raw mode).
- **The schema is where the plan's rules become `CHECK` constraints**, taking its limits from the same constants as the code ([Where rules are enforced](../guidelines/principles.md#where-rules-are-enforced) in [`docs/guidelines/principles.md`](../guidelines/principles.md)). Every table is `STRICT`, the one hand edit a new migration gets, and a test checks it.
- **Tests go through the same proxy adapter** in Node, so the path every tab uses is tested.
- drizzle-kit is the one tool that loads TypeScript through its own loader instead of Node's (see [0006](0006-node-type-stripping.md)).
